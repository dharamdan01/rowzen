# Rowzen: Correction Workspace refinement

Date: 27 October 2026 (Asia/Karachi).

## Delivered scope

This phase refines existing controls without adding a route, dependency, persistence mechanism, provider or repair strategy.

- Existing mapped issue-to-cell navigation retains physical CSV line/source-column identity. The editor shows original, current and proposed values locally, uses the shared Textarea and preserves its ref, Escape behavior and approval handler.
- The existing dataset/Undo/Redo/discard controls share a compact surface. State, pending edit, preview, history and component keys are unchanged.
- Manual What-if remains predicted/not applied. Its current/predicted metrics are easier to compare, with explicit business-correctness limits and existing introduced/resolved/remaining finding displays.
- AI strategy advice, the locally resolved candidate, deterministic simulation and applied correction are distinct stages. Guidance-only/ambiguous proposals retain investigation actions without value previews or Apply.
- Candidate value regions and the bounded activity timeline are keyboard-focusable and scrollable. No values or entries are truncated or removed. Existing filtering/page sizing/history limits remain.
- Original-vs-corrected comparison and automatic-revalidation notices remain tied to actual canonical results.
- Corrected CSV download retains its existing behavior and clear disclosure that formula-like values receive an apostrophe in the downloaded file; the browser-memory snapshot is not transformed in place.

## Supplied-pack behavior

Inputs are unchanged samples/csv_fixtures/05_ai_repair/boolean_review.csv and 06_export/escaping_unicode.csv. Source active maps to target is_active; description maps to details. Validation and raw correction addresses remain distinct through the existing mapping resolver.

- Initial applied configuration has two INVALID_TYPE findings (yes/maybe under boolean validation), eight records and two invalid rows.
- Previewing explicit manual yes -> true resolves one finding, changes no snapshot/history, and does not claim the remaining maybe value is correct.
- After that approved correction, previewing an empty required multiline description introduces one finding (one -> two total issues); Cancel preserves the current cell.
- An explicit nonempty multiline text edit has neutral preflight impact and may still be approved manually under the existing manual workflow. It is never generated by the model.
- Undo/Redo restores exact snapshots and records actual actions. Expected-value checks reject reuse of an outdated edit.
- Downloaded corrected CSV reparses with the approved multiline value, unchanged Unicode in other cells, original source headers and leading-zero postal strings. Formula-like text is deliberately apostrophe-prefixed only in the export, as disclosed by the UI. Original upload preview remains unchanged.

Manual and AI approval have their existing distinct rules: manual edits remain user-controlled, including previews with negative impact; AI Apply requires the existing fresh, supported, verified preflight improvement. This UI phase does not weaken either policy or claim business correctness.
